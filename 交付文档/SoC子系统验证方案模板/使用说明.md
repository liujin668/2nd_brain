# SoC子系统验证方案模板使用说明

本模板供各子系统验证负责人及验证工程师填写，用于方案评审、执行跟踪和交付验收。建议每个子系统复制一份，填写自己的配置、责任边界和证据。

## 放到飞书文档

本次模板以 `SoC子系统验证方案模板.md` 为正文，配套 `assets/` 中的 14 张示意图及 HTML 预览文件。

1. 在飞书云文档中选择本地文件导入功能，将该 Markdown 文件导入为可编辑的飞书云文档。
2. 不要仅将文件作为附件上传；附件留存不等于已创建可编辑的模板文档。
3. Markdown 中的相对图片路径不保证被飞书自动带入。请按正文图号，从 `assets/` 中手动插入对应示意图，或直接插入本子系统的实际图片。
4. 导入后检查章节层级、表格列宽、图号和图注，尤其是较宽的表格。必要时在飞书中调整。

具体入口可参考[飞书官方说明：上传或导入本地文件和文件夹](https://www.feishu.cn/hc/zh-CN/articles/360033241654-上传或导入本地文件和文件夹)。

## 填写与替换

- 保留原有章节编号和章节名称，便于各子系统方案统一评审。
- 将 `【填写】` 及其他方括号提示替换为实际内容；表格按实际需要增加记录。
- 将“示意占位”图片替换为本子系统的框图、时序图、状态图或统计图，并同步更新图注。
- 不适用项填写 `N/A` 或“不适用”，同时说明原因及确认人；待定项填写责任人和计划解决时间。
- 需求、验证点、场景、用例、检查器和问题单使用稳定 ID。详细清单可以放在飞书表格或代码仓，并在方案中保留版本及链接。

第 1 至 6 章主要填写计划与约定。第 7 章先明确统计口径，执行后再按实际报告基线填写结果；记录设计、环境、工具、配置、回归及覆盖率数据的版本。不要把示例、目标或占位文字当作实际结果，也不要将缺少数据填写为“通过”或“100%”。

## 本地阅读和复制

`SoC子系统验证方案模板.md` 使用 `assets/` 下的相对图片路径。阅读或迁移 Markdown 时，应保持 Markdown 文件和 `assets` 文件夹的相对位置。

可用浏览器打开配套 HTML 文件，预览排版并复制正文和表格到飞书。HTML 中的简图和统计图位都是示意占位，需在填写时替换。

无论导入 Markdown，还是从 Markdown 或 HTML 复制内容，都不要假定图片会一并进入飞书；未显示的图片需手动插入。粘贴后也应检查标题层级和表格格式。

## 文件组成

- `SoC子系统验证方案模板.md`：模板正文，可导入飞书或进行文本编辑和版本管理。
- HTML 预览文件：供本地浏览及复制正文、表格。
- `assets/`：14 张示意图和图表占位，供手动插图或替换参考。
- `使用说明.md`：本说明。

正式评审前，检查所有占位提示、未确认事项和链接，保留必要的修订与评审记录。
