# 测试计划与阶段验收矩阵

下表定义后续完整工程的验收范围。它是一份测试计划，不表示所有用例已经实现。当前模板实现和实测状态以README、docs_sv.md、docs_flow.md和验证记录为准。

## 阶段与证据

| 阶段 | 有效证据 | 不能替代的证据 |
| --- | --- | --- |
| 工具链mock | 脚本能分类正常/失败/异常、产生报告与复现信息 | SV编译、协议、RTL或CPU行为 |
| UVM自检 | synthetic transaction数据检查、UVM生命周期、静态clock/reset/SVA接线的实测结果 | AXI握手monitor、真实VIP或SoC路径 |
| AXI VIP | 实际master/slave接口、monitor、协议检查和memory模型 | CMN路由、一致性、CPU取指 |
| CMN BFM | 实际CMN节点、路由、协议转换和数据通路 | 未接入CPU的真实启动及内存序 |
| N2裸机 | 实际N2取指执行、DDR地址路径和软件硬件联合结束 | 被memory VIP替代的DDRC/PHY/DRAM电气与训练行为 |

## 每个阶段退出条件

1. 用例执行了预期场景，monitor确实观察到对应事件。
2. 必需checker存在并启用，正常路径通过，至少一次相关注错被识别。
3. 软件/事务/断言错误与最终报告一致，没有空PASS。
4. VCS和Xcelium按阶段要求分别验收；不把同seed解释为两工具产生逐项相同随机序列。
5. 失败可以使用记录的源码、配置、镜像和工具版本复现。
6. 未支持、未执行、已豁免和已通过分开统计，豁免附理由及评审记录。

## 代码评审检查表

- 编译宏与运行参数的边界明确，生成配置纳入依赖。
- 所有class只属于一个package，没有重复include/独立编译。
- 每个实际信号有明确owner，clock/reset在time zero有确定初态。
- 控制接口有请求/应答、超时和初始化约束。
- checker的reset关闭窗口不会遮盖reset自身的错误。
- memory参考值独立于实际响应模型，错误响应的副作用有定义。
- C/DPI/SV/VIP的地址宽度完整，R/W数据宽度单独处理。
- 软件结果有本次身份，cache可见性与结束语义明确。
- 镜像、stack、scratch、mailbox等区域不重叠。
- raw run结果不被预期失败suite或重试覆盖。
- 未接入的生产profile会明确拒绝执行。

## 最小系统完成的定义

最小系统验收必须包含真实N2、实际CMN路径、配置匹配的内存模型、真实裸机执行和全部必需checker。若仍处于VIP自检阶段，报告名称保持为“环境自检”，并列出接入真实系统所需的下一项输入。
