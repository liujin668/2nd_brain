## 3 本次静态审查落实的修正

- 时基统一为 `1ps`，用实际时钟边沿间隔核对配置周期，避免 `time` 在不同单位间传递造成千倍偏差。
- reset 检查避开首次采样与 NBA 更新的竞态，时钟和复位各有唯一物理驱动者。
- 有效写入字节及地址/控制进入模型前检查 X/Z；实际模型和参考模型保存四态字节，避免两端同时把 X 转成 0。
- 必需静态断言要有注册和采样证据；零错误但未绑定/未采样不满足通过条件。
- 负测精确核对失败 ID、计数和日志次数，额外重复的同 ID 错误不能被宽泛豁免。
- 断言日志解析覆盖实际的 `SOC_ASSERTION_ERROR` 前缀，结果落盘后的错误仍要使流程失败。
- ELF 装载地址与运行地址分别记录，导出的物理入口不被宣称为已验证的 CPU 启动地址。
- 软件结束结果采用 payload-first、state-last 的发布契约；原子性、缓存可见性和读取一致性需要目标平台实现。
- Windows 回归原子写文件使用短临时名，命令行 JSON 使用可移植编码，降低长路径和中文目录导致的流程错误。

## 4 UVM 首次接入的验收预期

以下数量是源码设计预期，尚未由 EDA 实测确认：

- `soc_selftest`：72 个事务、72 次检查、40 次读比较，PASS；
- `soc_selftest_mismatch`：完整完成后 FAIL，失败 ID 恰好是 `DATA_MISMATCH` 和 `UVM_ERROR`，对应一条 mismatch 错误；
- 全部检查结束、pending 为零、必需断言采样有效；
- VCS 和 Xcelium 各自独立构建和运行，不共用二进制快照或覆盖率数据库。

若实测不同，先定位原因；不能为了让回归绿色而修改期望、扩大错误豁免或删除检查。

## 5 内网优先完成的工作

1. 在现有服务器环境运行 Python 自测，接入已经可用的 VCS/Xcelium wrapper。
2. 两个工具分别编译 UVM 自检，执行正常、注错、超时、缺失结果及晚到断言错误测试。
3. 从已有 SNPS VIP 示例提取真实配置与 API，实现 memory adapter 和真实总线观察器。
4. 明确 CMN 型号、出口协议、初始化及地址路由，接入请求端 BFM 和对应目标模型。
5. 取得 N2 RTL、reset vector 和初始化规范，补 startup/linker/装载映射和软件结束握手。
6. 在公司 LSF 上实现并验收提交、跟踪、取消和恢复，再启用集群 profile。
